# Session Log — June 21, 2026

## CSV Merge Pipeline + Extension Cleanup

### What we built

**`pipeline/merge_csvs.py`** — standalone script that left-joins the extension's video-analytics CSV with its follower-history CSV on exact `post_date`. Each video row gains a `follower_count_at_post` column (the creator's follower count on the day the video was published). Supports multi-file inputs, warns on unmatched dates instead of dropping rows, and drops `data_quality == 'no_data'` rows from the follower side before joining. Pandas added as a `pipeline/` dependency.

Committed earlier in `5f920ea` before this session; the rest of today's work cleans up the inputs feeding it.

### What we changed in the extension

**Removed in-popup tab-open buttons.** TikTok blocks/redirects when the extension calls `chrome.tabs.create` / `chrome.tabs.update` against `tiktokstudio` URLs, so the "Open my Content page" / "Open my Followers analytics" buttons and their `is-studio-page` / `is-followers-page` content-script checks were stripped out. The popup now assumes the active tab is already on the right page and shows guidance text reminding the user to navigate there before extracting. Audit: nothing breaks — `chrome.tabs.query` / `sendMessage` still need the `tabs` permission, the `'idle'` HTML pane was correctly dropped from `showOnly()`'s iteration, and the `activeTabId` capture-once behavior was already in place.

**Slimmed the video CSV.** Removed `views`, `likes`, `creator_uid`, `creator_handle`, `follower_count`, `account_created_date` — TikTok's insight payload never populated them. Touched:

- `popup.js` — `VIDEO_CSV_COLUMNS`
- `lib/parsers.js` — `parseInsightResponse` no longer emits those fields
- `background.js` — dropped the `fetching-profile` post-step (profile fetch + per-row back-fill) and the now-unused `formatUnixDate` / `formatUnixTime` imports
- `tests/parsers/parseInsightResponse.test.js` — assertions updated
- `pipeline/merge_csvs.py` — dropped the `creator_uid` dtype hint

**Restored `data_quality`** after the first pass removed it. It is partially populated (`insufficient_data` from TikTok's `status: 2`, `missing_ecr` when the 5-second retention point is absent) and worth keeping as a downstream filter signal.

Tests: 15/15 passing after the cleanup.

### Caveats captured

Wrote `outputs/2026-06-21-extension-cleanup-caveats.md` documenting:

1. **Multi-creator merging is no longer safe.** With `creator_uid` gone from the video CSV, `merge_csvs.py` always falls through to the date-only branch. Single-creator runs are correct; two creators' CSVs concatenated will cartesian-blow on any shared date. Run the merge per-creator, or restore an identity column (e.g., derived from filename) when a second participant lands.
2. **`data_quality` token semantics** — only ever empty, `insufficient_data`, or `missing_ecr`. Downstream filters should match exact tokens.
3. **True account-creation date is unobtainable** from TikTok. The agreed proxy is `creator_age_at_post_days = post_date − min(post_date) per creator_uid`, computed downstream of the merge. Underestimates real age when TikTok Studio truncates the export — already noted in `outputs/2026-06-09-feature-engineering-notes.md` and queued for Methodology §4.1.
4. **`follower_count_at_post` can be `NaN`.** Left-join keeps unmatched videos; downstream code must decide whether to drop, impute, or fail.
5. **Auto-open buttons are gone** — users navigate to TikTok Studio themselves. Extracting from the wrong page surfaces an error in the popup, not silent corruption.
6. **Profile interception still runs.** Don't strip `PROFILE_RE` / `ingestProfile` — the follower CSV uses `state.profile` to fill `creator_handle` / `creator_uid` on its rows.

## Multi-creator merge pipeline — design + plan + implementation (branch: feat/multi-creator-merge)

**Decisions made**
- Identity source: Google Form intake roster (`roster.csv`).
- File↔creator binding: filename slug (handle, sanitized identically to the extension).
- Roster schema: `pseudonymous_id`, `creator_handle` (join-only, dropped from output), `consent_form_id`, `donation_date`. Categorical fields (`niche`, `follower_bracket`, `audience_geo`) — schema TBD; tracked as open item.
- Anonymization: strip `creator_handle` and `creator_uid` from `dataset.csv`.
- Scope: merger only — no engineered features (cyclic encodings, `creator_age_at_post_days`, `videos_posted_before`) in this pass.
- Validation: strict-only mode. Collect every problem, abort once, no partial output.
- Approach B (pre-stamp then one big join): closes Caveat #1 cartesian bug because the join key includes `pseudonymous_id`.
- New script `pipeline/build_dataset.py`; `pipeline/merge_csvs.py` unchanged.
